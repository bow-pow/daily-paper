APOLLO: SGD-like Memory, AdamW-level Performance

Hanqing Zhu, Zhenyu Zhang, Wenyan Cong, Xi Liu, Sem Park, Vikas Chandra et al.
The Brief

This research introduces a new, memory-saving method for training very large AI models, like the ones that power chatbots.

The core idea is that the popular AdamW optimizer, while effective, uses a lot of memory to keep track of how to adjust the model's learning rate. APOLLO simplifies this process by using a clever approximation based on random projections, essentially creating a smaller, "low-rank" representation of the optimizer's state. This allows it to achieve similar training performance to AdamW but with drastically reduced memory requirements. Even a very small version, APOLLO-Mini, outperforms AdamW while using as little memory as a simpler optimizer called SGD.

This is exciting because it means we can train bigger and better AI models more efficiently, potentially making advanced AI more accessible and faster to develop, even on less powerful hardware.

Background

Training very large language models (LLMs) like GPT-3 or LLaMA requires an enormous amount of computational power and memory. A significant portion of this memory burden comes from the optimizer, a crucial component that helps the model learn by adjusting its internal parameters. The most popular optimizer, AdamW, is particularly memory-hungry because it keeps track of two "momentum" values for each parameter. This means that for every parameter in the model, AdamW needs to store three copies of information: the parameter itself, and two momentum values. This memory overhead forces researchers to use more expensive hardware, more GPUs, or smaller "batch sizes" (the number of training examples processed at once), all of which can slow down or limit the training process. While other memory-saving optimizers exist, they often involve complex and slow calculations (like Singular Value Decomposition, or SVD) or still require substantial memory to perform well.

What they did

This research proposes a new optimizer called APOLLO (Approximated Gradient Scaling for Memory-Efficient LLM Optimization). The core idea is to simplify how AdamW adjusts its learning rate, which is how much it changes a parameter at each step. The researchers observed that AdamW's element-wise adjustments (changing each parameter's learning rate individually) are more detailed than necessary for LLMs. They found that grouping parameters into "channels" (like columns in a matrix) and applying a single learning rate adjustment to all parameters within that channel is sufficient.

To make this memory-efficient, APOLLO doesn't calculate these channel-wise adjustments directly from the full AdamW momentum values. Instead, it uses an "auxiliary low-rank optimizer state." This means it takes a compressed, lower-dimensional version of the gradient (the direction of steepest ascent for the loss function) using a technique called "random projection." Random projection is a way to reduce the dimensionality of data without losing too much information, and importantly, it's much faster and less memory-intensive than SVD. APOLLO then computes the momentum values on this compressed, low-rank representation and uses them to derive the channel-wise scaling factors.

For extreme memory savings, they developed APOLLO-Mini, which further simplifies this by using a "rank-1" space and a "tensor-wise" scaling factor (a single scaling factor for an entire tensor or layer). This dramatically reduces the memory needed for the optimizer states, bringing it down to levels comparable to the much simpler SGD optimizer.

What they found

The experiments show that APOLLO and APOLLO-Mini achieve performance comparable to, and often better than, AdamW, while using significantly less memory for optimizer states. For instance, APOLLO-Mini can achieve "SGD-level memory costs" but outperform AdamW. In pre-training experiments on LLaMA models, APOLLO and APOLLO-Mini consistently outperformed AdamW, showing up to a 2.8 reduction in validation perplexity (a measure of how well the model predicts text).

Crucially, APOLLO offers substantial system-level benefits. On an 8-GPU setup, APOLLO achieved up to 3x higher training throughput compared to AdamW by allowing for 4x larger batch sizes. APOLLO-Mini even enabled the pre-training of a LLaMA-13B model on standard A100 GPUs without needing complex system optimizations. Furthermore, by combining APOLLO-Mini with weight quantization (reducing the precision of model weights), they demonstrated pre-training a LLaMA-7B model on a single GPU using less than 12 GB of memory, a significant breakthrough for accessibility. The paper also shows that APOLLO works well with random projection, avoiding the slow SVD operations that plague other memory-efficient methods.

Why it matters

This work makes training large language models much more accessible and efficient. By drastically reducing the memory required by the optimizer, APOLLO allows researchers and developers to:

*

Train larger models on less hardware

The ability to train models like LLaMA-7B on a single GPU with 12GB of memory democratizes LLM training, making it feasible for individuals and smaller institutions. *

Speed up training

The increased throughput means training can be completed much faster, saving time and computational costs. *

Improve scalability

APOLLO-Mini's ability to train larger models like LLaMA-13B without complex system setups simplifies the process of scaling up.

Essentially, APOLLO offers a way to get the performance benefits of sophisticated optimizers like AdamW without their prohibitive memory costs, making cutting-edge LLM development more practical and widespread.
