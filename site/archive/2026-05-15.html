Concurrency without Model Changes: Future-based Asynchronous Function Calling for LLMs

Guangyu Feng, Huanzhi Mao, Prabal Dutta, Joseph E. Gonzalez
The Brief

This research introduces a new way for AI language models to use external tools, like calculators or databases, much faster.

The core innovation is a system called AsyncFC that lets the AI work on generating its next response *while* a tool it called is still running, instead of waiting for it to finish. This is like a chef prepping the next dish while the oven is still cooking the first one. It achieves this by treating the results of tool calls as "futures" – placeholders for information that will be available later – which the AI can reason about even before the tool is done. This system works with existing AI models and tools without needing any special training.

This is interesting because it could make AI assistants and agents much more responsive and efficient, allowing them to handle complex tasks more quickly without sacrificing accuracy.

Background

Large Language Models (LLMs) are increasingly being used as "agents" that can interact with the real world by calling external tools or functions. Think of an LLM agent needing to check the weather, book a flight, or search a database. The standard way this works is synchronous: the LLM asks the tool to do something, then it has to *wait* for that tool to finish its job and report back before it can do anything else, like ask for another tool or give a final answer. This waiting period, especially if the tool takes a long time, significantly slows down the entire process, making the LLM agent feel sluggish. Previous attempts to fix this often involved changing how the LLM itself works or making the tools more complicated.

What they did

This research introduces a new system called AsyncFC (Asynchronous Function Calling). The core idea is to separate the LLM's thinking process (decoding) from the actual execution of the tools (function execution). Instead of waiting for a tool to finish, AsyncFC immediately tells the LLM that the tool *will* finish eventually, represented by a "future" placeholder. The LLM can then continue thinking and even plan its next steps, potentially calling other tools, while the first tool is still running in the background. This is similar to how you might start a long download on your computer and then continue browsing the web without waiting for the download to complete.

AsyncFC achieves this by working at the "execution layer," meaning it doesn't require any changes to the LLM itself or how the tools are written. It intercepts the function calls the LLM makes. When a function is called, AsyncFC dispatches it to run asynchronously and immediately gives the LLM a "future" object. This future is like a promise that the result will be available later. The LLM can then use these futures as if they were the actual results, or it can explicitly ask for the result using a special `await_future` function when needed.

Furthermore, AsyncFC introduces "dependency-aware scheduling." This means it can figure out which function calls can run at the same time (in parallel) and which ones *must* wait for others to finish because they depend on the results. This is done by allowing developers to optionally provide "annotations" that describe what data a function reads or writes. This prevents "race conditions" (where conflicting operations happen at the same time) and allows for more efficient parallel execution.

What they found

The experiments show that AsyncFC significantly speeds up LLM agents without sacrificing accuracy. On standard function-calling benchmarks (like the Berkeley Function Calling Leaderboard), AsyncFC achieved speedups of up to 1.26 times compared to traditional synchronous methods. When applied to more complex tasks like software engineering (using SWE-bench Lite), it provided even larger speedups, reaching 1.44 times faster. The research also found that LLMs seem to have a "native capability" to understand and reason about these "future" placeholders, meaning they can work with these asynchronous concepts without needing to be specifically trained for them. This suggests that the LLM can naturally handle these symbolic representations of future results.

Why it matters

This work is important because it offers a practical way to make LLM agents much faster and more responsive, especially when they need to interact with tools that take time to complete. By decoupling the LLM's thinking from tool execution, AsyncFC unlocks significant performance gains. This is crucial for building more capable and efficient AI systems that can handle complex, real-world tasks. The finding that LLMs can natively reason over futures is particularly exciting, as it opens up new possibilities for designing more sophisticated asynchronous interactions between LLMs and their tools, without requiring complex model retraining or modifications. The main takeaway is that by intelligently managing the execution of tools in the background, we can make LLM agents feel much snappier and more capable.
